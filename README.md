# 和风天气订阅推送（astrbot_plugin_qweather）

基于和风天气 QWeather 的天气查询与主动推送。**所有配置都在对话里完成**，插件配置项只放
系统默认 key。

- **多地址**：一个会话可以绑多个地点，每个地址有独立的推送方案
- 定时推送：每天 / 每周 / 每月 / 每小时 / 日出日落前后，内容分项可选
- 雨雪提醒：降水即将开始、即将结束时提醒，可配多个可提醒时段
- 灾害预警：轮询推送，同一条不重复推、等级升高再推
- 会话级凭据：不同群/私聊可以用自己的和风账号，随时恢复默认
- 额度查询：账户余额与最近 24 小时请求量

零额外依赖：Ed25519 签名和 JWT 用标准库实现，不需要 `cryptography` / `PyJWT`。

## 安装

把 `astrbot_plugin_qweather/` 整个目录放进 AstrBot 的插件目录：

| 部署方式 | 路径 |
|---|---|
| Docker（飞牛 NAS 等） | `/vol1/1000/docker/astrbot/data/plugins/` |
| 裸装 | `AstrBot/data/plugins/` |

放进去后在 WebUI 的插件管理里重载，日志出现 `[和风天气] 已启动` 即成功。

## 首次配置

两条路，任选其一。

**A. 系统默认 key（推荐，配一次全局可用）**

WebUI → 插件配置，填四项：

```
iss            开发者 ID       控制台 → 设置，Q 开头 10 位
sub            项目 ID         控制台 → 项目管理，点进项目可见
kid            凭据 ID         创建凭据并上传公钥后显示
host           API Host        控制台 → 设置，形如 xxxx.re.qweatherapi.com
private_key    私钥 PEM        三行 PEM 全文粘贴（Ed25519）
```

公钥在控制台创建凭据时上传。忘了公钥是哪个，发 `/key 公钥` 能看到系统私钥对应的那串。

**B. 会话专用 key**

```
/key 设置      → 分五步引导：iss → sub → kid → host → 私钥（可发「跳过」复用系统私钥）
/key           → 看当前用的是哪套
/key 默认      → 恢复系统默认
/key 校验      → 用当前 key 打一次实时天气
```

引导 5 分钟内有效，发「取消」中断。**私钥必须和该账号控制台里上传的公钥成对**，用别人的
iss/sub/kid 配自己的私钥只会得到 401。

## 指令

### 设置地区：全部可用方法

一共有 **6 种**写法，都通过对话完成，不需要改配置文件。

| # | 写什么 | 作用 | 会建新地址吗 |
|---|---|---|---|
| 1 | `/天气 设置 天津` | 把**当前地址**的地点改成天津 | 没有地址时建一个 |
| 2 | `/天气 设置 117.21,39.13` | 同上，用坐标（更精细） | 没有地址时建一个 |
| 3 | `/地址 加 天津` | **新增**一个地址并切过去 | 是 |
| 4 | `/地址 加 117.21,39.13 名称=公司` | 新增地址 + 起别名 | 是 |
| 5 | `/地址 改 2 地点=武清` | 把第 2 个地址改绑到武清 | 否 |
| 6 | 首次发 `/天气`，机器人反问后直接回 `天津` 或 `117.21,39.13` | 建第一个地址 | 是 |

只查不改：`/天气 杭州`、`/地址 查 2` 都是临时查询，不动任何配置。

改完地点后**原有的推送规则保留**，直接作用在新地点上。

#### 城市名最多到区县

地理编码只有省 / 市 / 区县三级，乡镇街道查不到——搜「杨柳青」直接返回 400：

| 写法 | 结果 | `name` / `adm2` |
|---|---|---|
| `/天气 设置 浙江省` | 落到杭州 | 杭州 / 杭州 |
| `/天气 设置 杭州` | 市级 | 杭州 / 杭州 |
| `/天气 设置 萧山` | 区县级 | 萧山 / 杭州 |
| `/天气 设置 武清` | 区县级 | 武清 / 天津 |
| `/天气 设置 天津 武清` | ❌ 查不到 | 越级写会 400 |

市级和区县级的区别不只是显示，还影响**预警推送范围**：绑定市级收全市下辖所有区县的
预警；绑定区县级只收本区的，不会跨区误推。

#### 坐标：顺序固定「经度,纬度」

```
/天气 设置 117.21,39.13     经度,纬度（正确）
/天气 设置 117.21 39.13     空格分隔，等价
/地址 加 117.21，39.13      中文逗号也行
```

**经度在前、纬度在后，不做自动判断。** 这跟和风 API 的 `location` 参数、以及 GeoJSON /
Google Maps 的写法一致。写反了会直接告诉你正确写法：

```
坐标顺序是「经度,纬度」——经度在前，纬度在后。
你写的 39.13,117.21 纬度超了 ±90，应该是 117.21,39.13。
```

不自动判序是故意的。以前按「哪个超过 90 哪个是经度」猜，看似聪明，但中国境内经度 73~136、
纬度 3~54，两个区间有重叠，经度小于 90 的地方（乌鲁木齐 87.62、拉萨 91.11 附近）会猜错，
而且用户永远不知道到底该按哪个顺序写。

小数位统一截到 2 位（0.01° ≈ 1.1 km），再多位没有对应精度的数据。

坐标会反查最近的行政区补名字，显示成 `天津市·和平（117.21,39.13）`，预警按该区县精确匹配。

实测同一时刻天津几个点的差异（2026-10-29 17:40）：

| 点位 | 温度 |
|---|---|
| 和平（天津站旁） | 17.58 °C |
| 武清城区 | 16.34 °C |
| 盘山（蓟州山区） | 15.13 °C |
| 塘沽海边 | 16.67 °C |

### /地址

一个会话最多 20 个地址，每个地址**独立**保存：推送规则、雨雪开关与时段、预警阈值与时段、
去重状态。两个地址绑同一个城市也互不干扰。

```
/地址                          列出所有地址（▶ 标记当前地址）
/地址 加 天津                  新增地址，自动成为当前
/地址 加 117.21,39.13          用坐标新增
/地址 加 天津 名称=公司        带别名，方便区分
/地址 用 2                     切换当前地址（也可以写 用 公司）
/地址 改 2 名称=家             改别名
/地址 改 2 地点=武清           改绑地点，规则保留
/地址 删 2                     连同它的全部推送方案一起删
/地址 查 2                     查该地址的天气，不切换
```

列表长这样：

```
地址列表（每个地址的推送方案各自独立）：
▶ 1. 家｜天津市·和平（117.21,39.13）（2 条推送，雨雪开，预警开）
　 2. 公司｜天津市·武清（1 条推送）
```

同一地点不会重复添加；只剩一个地址时不允许删除（否则就没得查了）。

### /天气

```
/天气                查当前地址的天气
/天气 杭州           临时查另一个地点，不改配置
/天气 设置 天津      把当前地址改成天津
/天气 清除           删掉当前地址
```

第一次直接发 `/天气`，机器人会反问地点，90 秒内回一个城市名或坐标即可。

### /天气推送

**作用在当前地址上。** 想给别的地址加规则，不必先切换，加 `地址=2`（或 `地址=别名`）即可。

```
/天气推送                                       列出当前地址的所有规则
/天气推送 加 每天 07:30 内容=now,daily,sun       每天 7:30
/天气推送 加 每周 一,三,五 07:30 内容=daily,air  每周一三五
/天气推送 加 每月 1,15 09:00 内容=daily,indices  每月 1 号和 15 号
/天气推送 加 每小时 8-20 0,30 内容=now,air       8~20 点，每小时 00 分和 30 分
/天气推送 加 日出 -30 内容=now,daily,sun         日出前 30 分钟
/天气推送 加 日落 +15 内容=now                   日落后 15 分钟
/天气推送 改 1 时间=08:00 内容=now,daily,air     改第 1 条
/天气推送 改 1 标题=早报                         给规则起名，推送标题会用它
/天气推送 开 1　　关 1　　删 1
/天气推送 试 1                                   立即渲染一次给你看，不发到频道
/天气推送 加 每天 09:00 地址=公司 内容=now        给「公司」这个地址加规则，当前地址不变
```

内容项：

| key | 内容 | 额外调用 |
|---|---|---|
| `now` | 实况：温度/体感/天气/风/湿度/气压/能见度 | 1 |
| `daily` | 今天+未来 3 天 | 1 |
| `hourly` | 未来 12 小时 | 1 |
| `air` | AQI + 首要污染物 | 1 |
| `indices` | 运动/洗车/穿衣/紫外线 4 项 | 1 |
| `alert` | 当前生效预警（没有就不显示） | 1 |
| `sun` | 日出日落 | **0**（从 daily 里取） |
| `minutely` | 未来 2 小时分钟降水 | 1（仅中国） |

`每小时 8-20 0,30` 的意思是「8 点到 20 点之间，每小时的 00 分和 30 分」，一共 26 次/天。

### /雨雪提醒

同样作用在当前地址。`地址=` 修饰符对下面所有指令都有效。

```
/雨雪提醒                     查看当前地址的配置
/雨雪提醒 开　　关
/雨雪提醒 加时段 08:00-12:00
/雨雪提醒 加时段 11:00-20:00   可加多个，命中任一时段就提醒
/雨雪提醒 列时段
/雨雪提醒 删时段 2
/雨雪提醒 间隔 10              轮询间隔（分钟，5-60）
/雨雪提醒 提前 60              提前多少分钟算「即将」
/雨雪提醒 开始 开　　结束 关    分别控制开始/结束提醒
```

时段支持跨零点写 `22:00-06:00`。不配时段等于全天可提醒。

### /预警推送

同样作用在当前地址，每个地址可以设不同的等级阈值和静默时段。

```
/预警推送               查看当前地址的配置
/预警推送 开　　关
/预警推送 间隔 60       轮询间隔（分钟，5-360），默认 60
/预警推送 等级 橙       最低推送等级：蓝/黄/橙/红
/预警推送 升级 开       等级升高时是否再推一次
/预警推送 加时段 07:00-23:00
/预警推送 删时段 1
/预警推送 测试          手动查一次当前预警
```

### /额度

```
/额度      余额、本月应计、最近 24 小时请求量
```

**需要先在控制台开通权限**（默认关闭）：

1. 控制台 → 项目管理 → 点开凭据
2. 下滑到「控制台权限」
3. 勾选「允许访问财务汇总数据」和「允许访问请求量统计」
4. 保存

没开通时接口返回 `403 Security Restriction`，插件会直接提示你去做这一步。

另外：`/metrics/v1/stats` 只给最近 24 小时，**不是当月累计**。免费订阅的月度额度不在资源包
里，接口看不到剩余量——想看月度总量得自己在控制台看。

## 推送成本

| 模块 | 计算 | 次/月 |
|---|---|---|
| 灾害预警 | 1 次/小时，**一次调用覆盖全国所有地区** | 720 |
| 定时预报 | 10 条规则 × 2 次/天 | 600 |
| 雨雪提醒（1 城市，窗口 12h，10 分钟间隔） | 6/h × 12h × 30 | 2160 |
| 用户查询 | 500 次 × 4 | 2000 |

免费订阅 5 万次/月，余量充足。真正随规模增长的是雨雪提醒：**每多一个地址，月增约 2160 次**。
多个地址绑同一个城市时，预警列表仍然只拉一次（全局共享），不会翻倍。

已做的成本控制：

- 预警用 `/v7/warning/list?range=cn` 全局列表，一次调用覆盖所有城市，只有城市真在列表里
  才去查详情。所以**预警成本与用户数无关**。
- 雨雪提醒先用逐小时预报的降水概率预筛，概率为 0 整轮跳过，不碰分钟降水接口；逐小时结果
  缓存 1 小时。
- 分钟降水只有中国区有数据，海外城市不要开雨雪提醒。

## 已知限制

- **分钟级降水只有中国**。海外城市雨雪提醒会一直查不到数据。
- **纯文本输出**，没有图文卡片。卡片要依赖容器里的 Typst/Playwright，渲染失败的代价是彻底
  收不到推送，先不做。
- **预警是轮询不是推送**。和风没有 webhook，任何声称"实时推送"的实现底层都是轮询。默认
  1 小时轮询，气象预警的提前量通常是 6-12 小时，够用。
- **预警列表是区县级**。市级 ID（如天津 `101030100`）不会出现在列表里，所以绑定市级时按
  LocationID 前 6 位（省市）前缀匹配才能覆盖下辖区县；绑定区县或坐标时改用精确匹配，否则
  会把全市预警都推过来。中国台湾省等地区的 ID 是 5 位字母数字，两种都走精确匹配。
- **地理编码到区县为止**。街道乡镇查不到（搜「杨柳青」返回 400），需要更细只能直接给坐标。
- **坐标精度约 1 km**。和风按网格插值，0.01° 以下的小数位会被截断，给再多位也没有更细的数据。
- **坐标顺序固定「经度,纬度」，不自动判序**。写反了会给明确报错和正确写法，但不会猜。原因见
  上文，自动判序在中国境内有猜错的区间。
- **一个会话最多 20 个地址**。再多的话说明该按群拆了。
- 进程卡住超过一分钟会漏推该分钟的规则。30 秒 tick 下基本不会发生。

## 文件

| 文件 | 职责 |
|---|---|
| `main.py` | 插件类，只放 handler 与生命周期 |
| `qw/jwtlite.py` | Ed25519 签名 + JWT 签发（标准库） |
| `qw/client.py` | 和风接口封装、归一化、错误分类 |
| `qw/keys.py` | 默认 key + 会话 key + 分步引导状态机 |
| `qw/store.py` | 地址、规则、配置、去重状态持久化（含 v1 单城市数据自动迁移） |
| `qw/schedule.py` | 规则引擎（纯函数，可单测） |
| `qw/render.py` | 纯文本渲染 |
| `qw/commands.py` | 指令执行（不依赖 AstrBot） |
| `qw/pushers.py` | 后台主循环与三个推送源 |
| `tests/test_offline.py` | 离线冒烟测试（桩模块替换 AstrBot，不联网） |

数据落在 `data/plugin_data/astrbot_plugin_qweather/`：`subs.json`（地址、规则、去重状态）、
`keys.json`（会话级 key）。**去重状态必须落盘**，否则重启会把当前所有预警重推一遍。

`subs.json` 结构：

```json
{"sessions": {"<umo>": {"active": "L3f2a", "locations": [
  {"lid": "L3f2a", "name": "公司", "city": {...},
   "rules": [...], "precip": {...}, "alert": {...},
   "state": {"alerts": {}, "precip": "dry", "fired": {"r1a2b3": "2026-10-30 07:30"}}}
]}}}
```

v1.1 及以前的「一个会话一个 city」结构会在加载时自动迁移成一个地址，配置不丢。

## 开发

```bash
# 离线冒烟测试：不需要 AstrBot、不需要网络、不消耗接口调用
python tests/test_offline.py
```

224 项，覆盖签名、规则引擎、存储（多地址隔离与旧数据迁移）、地址指令、推送循环、指令解析、渲染。涉及真实接口的部分
无法离线验证，装进 AstrBot 后实际跑一遍指令即可。

`main.py` 里的 `@filter.*` 必须留在 `main.py`——AstrBot 用 `handler_module_path` 精确匹配
handler 归属，写在其它模块会被静默丢弃。

代码风格用 ruff（配置见 `pyproject.toml`）：

```bash
ruff check . && ruff format .
```
