# 和风天气订阅推送（astrbot_plugin_qweather）

基于和风天气 QWeather 的天气查询与主动推送。**所有配置都在对话里完成**，插件配置项只放
系统默认 key。

- **多地址**：一个会话可以绑多个地点，每个地址有独立的推送方案
- 定时推送：每天 / 每周 / 每月 / 每小时 / 日出日落前后，内容分项可选
- 雨雪提醒：降水即将开始、即将结束时提醒，可配多个可提醒时段
- 灾害预警：轮询推送，同一条不重复推、等级升高再推
- 图片卡片：装了 Playwright 就顺带推一张图，先文字后图片；不装只发文字
- 会话级凭据：不同群/私聊可以用自己的和风账号，随时恢复默认
- 额度查询：账户余额与最近 24 小时请求量

零额外依赖：Ed25519 签名和 JWT 用标准库实现，不需要 `cryptography` / `PyJWT`。

## 安装

1. 把仓库 clone 或下载解压到 AstrBot 的插件目录 `data/plugins/astrbot_plugin_qweather`
   （目录名保持 `astrbot_plugin_qweather`，改了会读不到 `metadata.yaml` 而加载失败）。
2. 打开 WebUI → 插件，找到「和风天气订阅推送」，启用它；更新过代码就点一次「重载插件」。
3. 点插件卡片的配置页，填 `iss / sub / kid / host / private_key`（也可以先不填，让每个会话
   自己用 `/qweather key 设置`）。
4. 在群里发 `/qweather 帮助`，能收到指令表就装好了。

装好之后想直接上手，照 **[推荐配置](docs/推荐配置.md)** 抄七条命令就行：工作日早 8 点全量日报、
晚 21:30 复盘、只在上班时段盯雨雪和预警、每天 21:00 对额度，一个月约 1190 次请求、0 元。

日志里出现 `[和风天气] 已启动：…` 即成功；如果提示「加载失败」，先看日志里的 traceback，
多半是目录层级多套了一层（比如 `plugins/astrbot_plugin_qweather/astrbot_plugin_qweather/`）。

## 首次配置

两条路，任选其一。

**A. 系统默认 key（推荐，配一次全局可用）**

WebUI → 插件配置，填五项（`指令前缀` 有默认值，一般不用动）：

```
command_prefix 指令前缀        默认 qweather，不允许为空
iss            开发者 ID       控制台 → 设置，Q 开头 10 位
sub            项目 ID         控制台 → 项目管理，点进项目可见
kid            凭据 ID         创建凭据并上传公钥后显示
host           API Host        控制台 → 设置，形如 xxxx.re.qweatherapi.com
private_key    私钥 PEM        三行 PEM 全文粘贴（Ed25519）
```

另外三项是工作日日历的轮换日期，默认值就是下面这样，一般不用动：

```
next_year_fetch_date     11-01   从这天起每天 0 点试着拉次年放假安排，拿到就停
next_year_calendar_date  11-01   到这天算一次次年的周末日历
cleanup_date             02-01   到这天删掉更早年份的数据
```

公钥在控制台创建凭据时上传。忘了公钥是哪个，发 `/qweather key 公钥` 能看到系统私钥对应的那串。

> ⚠️ **要用额度功能，还得去控制台开权限。** 额度查询和额度推送走的是控制台 API，
> 默认全部关闭，不开就一直 403。要勾的四项在「控制台 → 项目管理 → 项目 → 凭据 →
> 下滑到控制台权限」，逐项见 [`/qweather 额度`](#qweather-额度) 一节。
> 只勾「汇总统计」不够——「指定项目」「指定凭据」两项必须在下拉里选中具体对象。

**配置保存即生效，不用重载插件。** AstrBot 的保存接口只写
`data/config/astrbot_plugin_qweather_config.json`，正在跑的插件实例仍拿着旧配置——很多
「面板里明明填了 key，插件却说没配」就是这么来的。本插件每次读配置前会 stat 一下这个文件，
mtime 变了就自动合并新值并重算系统默认 key，日志会打一行：

```
[和风天气] 配置已保存，自动重读：系统默认 key 就绪
```

> v1.5.3 之前的版本还有第二层原因：AstrBot v4.29 的 `Star.__init__` 不再把 `config` 存成
> `self.config`，插件没自己留一份，于是所有配置项都退化成默认值（key 永远显示「空」）。
> 现在插件自己持有配置副本，同时保留按文件 mtime 的热重读。

启动日志还会把「插件实际读到了什么」打出来，用来对照面板（值都打了码）：

```
[和风天气] 配置文件：/AstrBot/data/config/astrbot_plugin_qweather_config.json
[和风天气] 配置项 iss=Q9ST…（10 位）
[和风天气] 配置项 sub=3CTM…（10 位）
[和风天气] 配置项 kid=TDPP…（11 位）
[和风天气] 配置项 host=ne6y…（29 位）
[和风天气] 配置项 私钥=已载入（公钥 VATVQpX1…）
```

哪一项显示「空」，就是那一项没读到——要么没保存，要么填错了框。`/qweather key` 也会给出同样的
指纹，不用翻日志。

**B. 会话专用 key**

```
/qweather key 设置      → 分五步引导：iss → sub → kid → host → 私钥（可发「跳过」复用系统私钥）
/qweather key           → 看当前用的是哪套
/qweather key 默认      → 恢复系统默认
/qweather key 校验      → 用当前 key 打一次实时天气
```

引导 5 分钟内有效，发「取消」中断。**私钥必须和该账号控制台里上传的公钥成对**，用别人的
iss/sub/kid 配自己的私钥只会得到 401。

## 指令

### 指令前缀：为什么不是裸指令

所有指令都挂在一条主指令下面，写法是 `/前缀 子指令`：

- 默认前缀 `qweather`，也就是 `/qweather 天气`
- 前缀可以在插件配置的「指令前缀」里改，**但不允许为空**：留空、只填空格、只填 `/`
  都会自动回落成 `qweather`
- 改完前缀点「保存并关闭」就生效，不用重载插件（旧前缀立刻不再响应）

不给裸指令（`/天气`）是有原因的：AstrBot 把一条消息投给所有匹配的 handler，两个插件都注册
`/天气` 时，用户会同时收到两份天气，还分不清哪份算数。加一层前缀就没有这个歧义。同理，
`/qweather 天气` 和外面别的插件的 `/天气` 可以各自安好地并存。

下文所有示例都用默认前缀 `qweather`。

> **从 1.2 升级**：`/天气`、`/地址`、`/天气推送`、`/雨雪提醒`、`/预警推送`、`/key`、`/额度`
> 这些裸指令在 1.3 起**不再响应**，对应关系是 `/天气` → `/qweather 天气`、
> `/地址` → `/qweather 地址`、`/天气推送` → `/qweather 推送`、`/雨雪提醒` → `/qweather 雨雪`、
> `/预警推送` → `/qweather 预警`、`/key` → `/qweather key`、`/额度` → `/qweather 额度`。
> 已存的地址、规则、去重状态都不用重配。

### 设置地区：全部可用方法

一共有 **6 种**写法，都通过对话完成，不需要改配置文件。

| # | 写什么 | 作用 | 会建新地址吗 |
|---|---|---|---|
| 1 | `/qweather 天气 设置 天津` | 把**当前地址**的地点改成天津 | 没有地址时建一个 |
| 2 | `/qweather 天气 设置 39.13,117.21` | 同上，用坐标（更精细） | 没有地址时建一个 |
| 3 | `/qweather 地址 加 天津` | **新增**一个地址并切过去 | 是 |
| 4 | `/qweather 地址 加 39.13,117.21 名称=公司` | 新增地址 + 起别名 | 是 |
| 5 | `/qweather 地址 改 2 地点=武清` | 把第 2 个地址改绑到武清 | 否 |
| 6 | 首次发 `/qweather 天气`，机器人反问后直接回 `天津` 或 `39.13,117.21` | 建第一个地址 | 是 |

只查不改：`/qweather 天气 杭州`、`/qweather 地址 查 2` 都是临时查询，不动任何配置。

改完地点后**原有的推送规则保留**，直接作用在新地点上。

#### 城市名最多到区县

地理编码只有省 / 市 / 区县三级，乡镇街道查不到——搜「杨柳青」直接返回 400：

| 写法 | 结果 | `name` / `adm2` |
|---|---|---|
| `/qweather 天气 设置 浙江省` | 落到杭州 | 杭州 / 杭州 |
| `/qweather 天气 设置 杭州` | 市级 | 杭州 / 杭州 |
| `/qweather 天气 设置 萧山` | 区县级 | 萧山 / 杭州 |
| `/qweather 天气 设置 武清` | 区县级 | 武清 / 天津 |
| `/qweather 天气 设置 天津 武清` | ❌ 查不到 | 越级写会 400 |

市级和区县级的区别不只是显示，还影响**预警推送范围**：绑定市级收全市下辖所有区县的
预警；绑定区县级只收本区的，不会跨区误推。

#### 坐标：顺序固定「纬度,经度」

```
/qweather 天气 设置 39.13,117.21     纬度,经度（正确）
/qweather 天气 设置 39.13 117.21     空格分隔，等价
/qweather 地址 加 39.13，117.21      中文逗号也行
```

度分秒也认，从地图上抄坐标直接粘就行：

```
/qweather 地址 加 39°13'53",117°8'2" 名称=北辰公司     度° 分' 秒"，顺序还是纬度在前
/qweather 地址 加 39度13分53秒,117度8分2秒             中文单位
/qweather 地址 加 39°13′53″,117°8′2″                   全角撇号
/qweather 地址 加 39°13',117°8'                        只有度分
/qweather 地址 加 N39.23,E117.13                       十进制 + 方位词
```

度分秒必须**两个点都带符号**（`°` 和 `'`）。`39 13 53, 117 8 2` 这种纯数字串分不开哪个
是度哪个是分，插件会直接告诉你写清楚，不会瞎猜。

**纬度在前、经度在后，不做自动判断。** 这是地图上抄坐标的通行读法（`39°13'53",117°8'2"`），
也是「北纬 39°、东经 117°」的说法顺序。写反了会直接告诉你正确写法：

```
坐标顺序是「纬度,经度」——纬度在前，经度在后。
你写的是「经度,纬度」，第一个数 117.21 超过 ±90，那只能是经度。
改成：39.13,117.21
```

发给和风时才翻成它要的 `经度,纬度`（`location` 参数），这一步内部完成，不用管。

不自动判序是故意的。以前按「哪个超过 90 哪个是经度」猜，看似聪明，但中国境内经度 73~136、
纬度 3~54，两个区间有重叠，经度小于 90 的地方（乌鲁木齐 87.62、拉萨 91.11 附近）会猜错，
而且用户永远不知道到底该按哪个顺序写。

小数位统一截到 2 位（0.01° ≈ 1.1 km），再多位没有对应精度的数据。

坐标会反查最近的行政区补名字，显示成 `天津市·和平（39.13,117.21）`，预警按该区县精确匹配。

实测同一时刻天津几个点的差异（2026-10-29 17:40）：

| 点位 | 温度 |
|---|---|
| 和平（天津站旁） | 17.58 °C |
| 武清城区 | 16.34 °C |
| 盘山（蓟州山区） | 15.13 °C |
| 塘沽海边 | 16.67 °C |

### /qweather 地址

一个会话最多 20 个地址，每个地址**独立**保存：推送规则、雨雪开关与时段、预警阈值与时段、
去重状态。两个地址绑同一个城市也互不干扰。

```
/qweather 地址                          列出所有地址（▶ 标记当前地址）
/qweather 地址 加 天津                  新增地址，自动成为当前
/qweather 地址 加 39.13,117.21          用坐标新增
/qweather 地址 加 天津 名称=公司        带别名，方便区分
/qweather 地址 用 2                     切换当前地址（也可以写 用 公司）
/qweather 地址 改 2 名称=家             改别名
/qweather 地址 改 2 地点=武清           改绑地点，规则保留
/qweather 地址 删 2                     连同它的全部推送方案一起删
/qweather 地址 查 2                     查该地址的天气，不切换
```

列表长这样：

```
地址列表（每个地址的推送方案各自独立）：
▶ 1. 家｜天津市·和平（39.13,117.21）（2 条推送，雨雪开，预警开）
　 2. 公司｜天津市·武清（1 条推送）
```

同一地点不会重复添加；只剩一个地址时不允许删除（否则就没得查了）。

### /qweather 天气

```
/qweather 天气                查当前地址的天气
/qweather 天气 杭州           临时查另一个地点，不改配置
/qweather 天气 设置 天津      把当前地址改成天津
/qweather 天气 清除           删掉当前地址
```

第一次直接发 `/qweather 天气`，机器人会反问地点，90 秒内回一个城市名或坐标即可。

### /qweather 推送

**作用在当前地址上。** 想给别的地址加规则，不必先切换，加 `地址=2`（或 `地址=别名`）即可。

```
/qweather 推送                                       列出当前地址的所有规则
/qweather 推送 加 每天 07:30 内容=now,daily,sun       每天 7:30
/qweather 推送 加 每周 一,三,五 07:30 内容=daily,air  每周一三五
/qweather 推送 加 每月 1,15 09:00 内容=daily,indices  每月 1 号和 15 号
/qweather 推送 加 每小时 8-20 0,30 内容=now,air       8~20 点，每小时 00 分和 30 分
/qweather 推送 加 日出 -30 内容=now,daily,sun         日出前 30 分钟
/qweather 推送 加 日落 +15 内容=now                   日落后 15 分钟
/qweather 推送 改 1 时间=08:00 内容=now,daily,air     改第 1 条
/qweather 推送 改 1 标题=早报                         给规则起名，推送标题会用它
/qweather 推送 开 1　　关 1　　删 1
/qweather 推送 试 1                                   立即渲染一次给你看，不发到频道
/qweather 推送 加 每天 09:00 地址=公司 内容=now        给「公司」这个地址加规则，当前地址不变
```

想让它只在上班日推，加一个 `日=工作日`：

```
/qweather 推送 加 每天 07:30 内容=daily 日=工作日       法定节假日和周末跳过，调休上班日照推
/qweather 推送 加 每天 10:00 内容=daily 日=休息日       只在周末和节假日推
/qweather 推送 改 1 日=不限                             取消日条件
```

工作日按「周一到周五 + 调休上班日 - 法定节假日」算，数据来自下面的工作日日历。

内容项：

| key | 内容 | 额外调用 |
|---|---|---|
| `now` | 实况：温度/体感/qweather 天气/风/湿度/气压/能见度 | 1 |
| `daily` | 今天+未来 3 天 | 1 |
| `hourly` | 未来 12 小时 | 1 |
| `air` | AQI + 首要污染物 | 1 |
| `indices` | 运动/洗车/穿衣/紫外线 4 项 | 1 |
| `alert` | 当前生效预警（没有就不显示） | 1 |
| `sun` | 日出日落 | **0**（从 daily 里取） |
| `minutely` | 未来 2 小时分钟降水 | 1（仅中国） |

`每小时 8-20 0,30` 的意思是「8 点到 20 点之间，每小时的 00 分和 30 分」，一共 26 次/天。

内容也可以一次要全套，不用一个个敲：

```
内容=全部                8 项全要（注意：一次推送打 8 个接口，成本 ×8）
内容=全部除now           除实况以外全要
内容=全部除now,sun       除实况和日出日落
内容=全部-now            减号也行
```

`全部` 展开就是上表 8 项，`sun` 仍然不额外计费（从 daily 里取）。

### /qweather 雨雪

同样作用在当前地址。`地址=` 修饰符对下面所有指令都有效。

```
/qweather 雨雪                     查看当前地址的配置
/qweather 雨雪 开　　关
/qweather 雨雪 加时段 08:00-12:00
/qweather 雨雪 加时段 11:00-20:00   可加多个，命中任一时段就提醒
/qweather 雨雪 加时段 工作日 08:00-18:00   这个时段只在上班日生效
/qweather 雨雪 清时段                       清空后只留自己要的时段
/qweather 雨雪 列时段
/qweather 雨雪 删时段 2
/qweather 雨雪 间隔 10              轮询间隔（分钟，5-60）
/qweather 雨雪 提前 60              提前多少分钟算「即将」
/qweather 雨雪 开始 开　　结束 关    分别控制开始/结束提醒
```

时段支持跨零点写 `22:00-06:00`。不配时段等于全天可提醒。
时段前可以加 `工作日` / `休息日` 限定，不加就是每天；`列时段` 里会原样显示这个前缀。

### /qweather 预警

同样作用在当前地址，每个地址可以设不同的等级阈值和静默时段。

```
/qweather 预警               查看当前地址的配置
/qweather 预警 开　　关
/qweather 预警 间隔 60       轮询间隔（分钟，5-360），默认 60
/qweather 预警 等级 橙       最低推送等级：蓝/黄/橙/红
/qweather 预警 升级 开       等级升高时再推一次（默认开）
/qweather 预警 降级 开       等级降低时再推一次（默认开）
/qweather 预警 变化 开       升和降一起开关
/qweather 预警 加时段 07:00-23:00
/qweather 预警 加时段 工作日 08:00-18:00   只在上班日盯
/qweather 预警 删时段 1
/qweather 预警 清时段        一次清空，然后只加自己要的时段
/qweather 预警 测试          手动查一次当前预警
```

同一条预警只会推一次，除非等级变了。变化推送会在标题后标出来：

```
⚠️ 【北辰公司·北辰】黄色大风预警（↑ 蓝色→黄色）
⚠️ 【北辰公司·北辰】蓝色大风预警（↓ 黄色→蓝色）
```

新地址默认带一个 `07:00-23:00` 的时段（每天生效）。只想在上班时间盯的话，先
`清时段` 再加自己的，否则那个默认时段会把周末也带上。`/qweather 设置` 里能直接看到
当前所有时段。

### /qweather 工作日

```
/qweather 工作日              今天是不是工作日，下个工作日/休息日是哪天
/qweather 工作日 明天          也可以写 后天 / 11-01 / 2027-01-01
/qweather 工作日 状态         各年数据状态与轮换日期
/qweather 工作日 刷新         立刻检查一次（平时是自动跑的）
```

判断规则只有三条：调休上班日算工作日（哪怕是周六）、法定节假日算休息日（哪怕是周三）、
其余按星期几算。

**数据从哪来、什么时候抓**（这一套是从
[payroll_computation](https://github.com/szjmhxd/payroll_computation) 那类纯静态项目的思路
搬过来的，区别是这里能自己联网，所以做成了自动轮换）：

- 数据源是 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)，每年一份
  JSON，国务院公告整理。主源 jsdelivr，失败自动换 fastly / raw.githubusercontent。
- 插件加载时抓一次当年数据，顺手把当年的周末日历（全部周六周日）算出来落盘。
- **每年 11 月 1 日起，每天 0 点试着拉次年安排**。判断「有没有」看的是 JSON 里的 `days`
  是否非空——公布前那个文件是能访问的、但 `days` 是空数组，只看 404 会误判。拿到就永久停手，
  拿不到第二天再试。加载时如果已经过了 11-01，会立刻补一次，不用等到第二天。
- **每年 11 月 1 日生成一次次年的周末日历**（纯本地计算，不联网）。
- **每年 2 月 1 日清理旧年份**，但当前年和次年永远保留——判断「今天是不是工作日」要用。
  所以文件里最多三四年，实测一年约 7 KB，完全不会长胖。
- 这三个日期都能在插件配置里改（`next_year_fetch_date` / `next_year_calendar_date` /
  `cleanup_date`），格式 `MM-DD`，写错了自动回落默认值。

数据没到手时不会硬撑：当年退化成「周一到周五算工作日」，`/qweather 工作日` 会明确写
「未就绪，按周一至周五估算」，带 `日=` 条件的推送规则在这种年份里会**跳过不推**——宁可
少推一次，也不要在休息日早上把工作日报推给用户。

### /qweather 额度

```

```

输出长这样：

```

应计费用：本月 0.50　昨日 0.02
资源包：无（免费订阅额度不在资源包里，看不到剩余量）
今天 10-30（截至 11:20）：128 次，其中失败 3 次
昨天 10-29：4,561 次，其中失败 61 次
近 7 天日均：3,200 次
  今天按接口：Weather 100　Geo 28
```

「今天 / 昨天」不是接口直接给的。`/metrics/v1/stats` 只返回**最近 24 小时**，晚上 9 点查
的话窗口从昨天 9 点开始，昨天只剩 3 小时可见，切不出完整的一天。所以插件自己记账：

- 每次拉到统计，就按**本地日期**把每小时的数字分桶累加，写进 `usage.json`。
- 同一天取「已有值」和「新值」里较大的那个。窗口是滚动的，某一天露出的小时数只会越来越多，
  已过去的小时计数不会变，所以取大值就是取最全的那次，滑出窗口后自动定稿。
- 账本只留最近 60 天，一天几十字节。

**代价**：插件停机的那段时间补不回来（接口本身不给历史）。如果昨天整天没运行，昨天就是空的，
插件会直说「昨天：没有数据（插件昨天没运行过）」，不会编一个数字。

   - 「允许访问指定项目的请求量统计」→ 选你的项目（截图里的「2 个应用」）
   - 「允许访问指定凭据的请求量统计」→ 选你的凭据（截图里的「2 个凭据」）
5. 点「保存」

### /qweather 成本

**把当前设置折成每月的请求次数和钱**。一个命令回答「我这样配下来一个月要花多少」：

```
/qweather 成本          先列全部设置，再算成本（默认）
/qweather 成本 明细     只算成本
/qweather 成本 设置     只看设置
```

```
按 31 天一个月、其中 22 个工作日估算：

【北辰公司】
  1. 每天 08:00〔仅工作日〕｜全部内容　约 22 次/月 × 7 = 154 次
  2. 每天 21:30〔仅工作日〕｜全部除实况　约 22 次/月 × 6 = 132 次
  雨雪轮询 每 20 分钟　约 825 次/月
    （每轮查一次分钟降水）
  雨雪预筛 逐时预报　约 286 次/月
    （平均每天 9.2 小时落在时段内（已按工作日折减），逐时有 1 小时缓存）
  预警轮询 每 60 分钟　约 275 次/月
    （预警列表全局共享，多地址会摊薄）
  预警详情（列表命中才查）　约 275 次/月 × 0.05 = 14 次
    （按每 20 轮命中 1 次估，实际取决于有多少预警）

【本会话】
  1. 每天 21:00〔仅工作日〕　约 22 次/月 × 2 = 44 次

合计：约 1,730 次/月
成本：0.00 元/月（每月前 50,000 次免费，还剩 48,270 次余量）
```

计价口径按官方「天气和基础服务」档（插件用到的接口全在这一档里），累进阶梯：

| 每月请求量 | 单价（元/次） |
|---|---|
| 0 – 50,000 | 0（免费） |
| 之后 950,000 | 0.0007 |
| 之后 4,000,000 | 0.0005 |
| 之后 5,000,000 | 0.00035 |
| 之后 40,000,000 | 0.00015 |
| 之后 50,000,000 | 0.0001 |

所以**每月 5 万次以内一分钱不花**。按上面这套配置（一个月 1730 次）算，离免费额度还差
28 倍，正常使用基本不可能花钱。
官方示例（100 万次 ≈ 665 元）和这个公式算出来一致。

估算**含**插件的缓存折减：逐时预报缓存 1 小时、日出日落 30 分钟、预警列表全局 5 分钟一次。
估算**不含**你手动发指令查询的部分——那取决于人，不取决于设置。

## 推送成本

| 模块 | 计算 | 次/月 |
|---|---|---|
| 灾害预警 | 1 次/小时，**一次调用覆盖全国所有地区** | 720 |
| 定时预报 | 10 条规则 × 2 次/天 | 600 |
| 雨雪提醒（1 城市，窗口 12h，10 分钟间隔） | 6/h × 12h × 30 | 2160 |
| 额度推送（每天一次） | 2 次/次（财务汇总 + 请求量） | 60 |
| 用户查询 | 500 次 × 4 | 2000 |

免费订阅 5 万次/月，余量充足。真正随规模增长的是雨雪提醒：**每多一个地址，月增约 2160 次**。
多个地址绑同一个城市时，预警列表仍然只拉一次（全局共享），不会翻倍。

已做的成本控制：

- 预警用 `/v7/warning/list?range=cn` 全局列表，一次调用覆盖所有城市，只有城市真在列表里
  才去查详情。所以**预警成本与用户数无关**。
- 雨雪提醒先用逐小时预报的降水概率预筛，概率为 0 整轮跳过，不碰分钟降水接口；逐小时结果
  缓存 1 小时。
- 分钟降水只有中国区有数据，海外城市不要开雨雪提醒。
- 工作日数据一年只抓几次：当年一次、次年公告出来后一次，其余时间都在读本地 `workdays.json`，
  对额度的影响可以忽略。

## 图片卡片

推送默认**先发文字、再发一张图片**。图是 HTML 用 Chromium 截的，图标全部来自和风官方
[icons.qweather.com](https://icons.qweather.com/)。

```
pip install playwright
playwright install chromium        # 约 150 MB，容器里要重装一次
```

装好之后重启插件，日志里会出现：

```
[和风天气] Playwright 就绪，推送会附一张图片卡片
```

没装则是：

```
[和风天气] 未安装 Playwright，图片卡片关闭（只发文字）。需要图片：pip install playwright && playwright install chromium
```

两种情况**推送都正常**，只是少了图。图片发送失败（平台不支持、体积超限）也只记一行日志，
文字那条已经先落地了。

几点说明：

- **卡片不额外消耗请求**。图是用已经取到的数据画的，不会重新调接口。
- **图标第一次用才下载**，按 code 存进 `data/plugin_data/astrbot_plugin_qweather/icons/`，
  之后离线可用。图标站对非浏览器 UA 返回 403，插件下载时带了 UA，你手动 `curl` 拿不到是正常的。
- **需要中文字体**。容器里没有 `Noto Sans CJK` / `文泉驿` 之类的话，图上中文会是方块。
  Debian/Ubuntu 装一个：`apt install fonts-noto-cjk`。
- 想关掉：插件配置里把「推送时附一张图片卡片」取消勾选。

## 平台适配

插件只发**纯文本**，并且只用 `context.send_message(umo, chain)` 这一条主动发送路径，所以理论上
不挑平台。实际验证过的是 **QQ 官方机器人（qq_official）**：查询、定时推送、预警、额度推送都
走通了。

没有在 `metadata.yaml` 里写 `support_platforms`，是故意的——写了就等于承诺支持，而各平台对
**主动消息**的限制差别很大（QQ 官方有主动消息额度、钉钉/企微的富媒体支持也不一样）。你如果在
别的平台跑通了，欢迎反馈，我再补上声明。

## 已知限制

- **分钟级降水只有中国**。海外城市雨雪提醒会一直查不到数据。
- **图片卡片需要 Playwright**。装了（`pip install playwright && playwright install chromium`）
  就自动出图，没装就只发文字，不会报错。容器里还得有中文字体，否则图上会是方块。
- **预警是轮询不是推送**。和风没有 webhook，任何声称"实时推送"的实现底层都是轮询。默认
  1 小时轮询，气象预警的提前量通常是 6-12 小时，够用。
- **预警列表是区县级**。市级 ID（如天津 `101030100`）不会出现在列表里，所以绑定市级时按
  LocationID 前 6 位（省市）前缀匹配才能覆盖下辖区县；绑定区县或坐标时改用精确匹配，否则
  会把全市预警都推过来。中国台湾省等地区的 ID 是 5 位字母数字，两种都走精确匹配。
- **地理编码到区县为止**。街道乡镇查不到（搜「杨柳青」返回 400），需要更细只能直接给坐标。
- **坐标精度约 1 km**。和风按网格插值，0.01° 以下的小数位会被截断，给再多位也没有更细的数据。
- **坐标顺序固定「纬度,经度」，不自动判序**。写反了会给明确报错和正确写法，但不会猜。原因见
  上文，自动判序在中国境内有猜错的区间。
- **一个会话最多 20 个地址**。再多的话说明该按群拆了。
- **工作日日历依赖第三方整理的数据**。`holiday-cn` 每年跟着国务院公告更新，公告出来之前
  只有周末规则可用；数据源全都挂掉时也只会退化成「周一到周五算工作日」，不会让插件报错。
- **用量账本补不回来停机那段时间**。`/metrics/v1/stats` 只给最近 24 小时，插件顺手按天记账，
  停机期间的小时数就是缺的。缺了会明说，不会编数字。
- 进程卡住超过一分钟会漏推该分钟的规则。30 秒 tick 下基本不会发生。

```json
{"sessions": {"<umo>": {"active": "L3f2a", "locations": [
```

`lang=zh` 参数注入与显式覆盖、折行与逐时分栏、图片卡片在无 Playwright 时的降级。
涉及真实接口的部分无法离线验证，装进 AstrBot 后实际跑一遍指令即可。

`main.py` 里的 `@filter.*` 必须留在 `main.py`——AstrBot 用 `handler_module_path` 精确匹配
handler 归属，写在其它模块会被静默丢弃。

代码风格用 ruff（配置见 `pyproject.toml`）：

```bash
ruff check . && ruff format .
```
