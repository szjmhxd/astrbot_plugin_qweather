# 和风天气订阅推送（astrbot_plugin_qweather）

基于和风天气 QWeather 的天气查询与主动推送。**所有配置都在对话里完成**，插件配置项只放
系统默认 key。

- 定时推送：每天 / 每周 / 每月 / 每小时 / 日出日落前后，内容分项可选
- 雨雪提醒：降水即将开始、即将结束时提醒，可配多个可提醒时段
- 灾害预警：轮询推送，同一条不重复推、等级升高再推
- 会话级凭据：不同群/私聊可以用自己的和风账号，随时恢复默认
- 额度查询：账户余额与最近 24 小时请求量

零额外依赖：Ed25519 签名和 JWT 用标准库实现，不需要 `cryptography` / `PyJWT`。

## 安装

把 `astrbot_plugin_qweather/` 整个目录放进 AstrBot 的插件目录：

| 部署方式 | 路径 |
|---|---|
| Docker（飞牛 NAS 等） | `/vol1/1000/docker/astrbot/data/plugins/` |
| 裸装 | `AstrBot/data/plugins/` |

放进去后在 WebUI 的插件管理里重载，日志出现 `[和风天气] 已启动` 即成功。

## 首次配置

两条路，任选其一。

**A. 系统默认 key（推荐，配一次全局可用）**

WebUI → 插件配置，填四项：

```
iss            开发者 ID       控制台 → 设置，Q 开头 10 位
sub            项目 ID         控制台 → 项目管理，点进项目可见
kid            凭据 ID         创建凭据并上传公钥后显示
host           API Host        控制台 → 设置，形如 xxxx.re.qweatherapi.com
private_key    私钥 PEM        三行 PEM 全文粘贴（Ed25519）
```

公钥在控制台创建凭据时上传。忘了公钥是哪个，发 `/key 公钥` 能看到系统私钥对应的那串。

**B. 会话专用 key**

```
/key 设置      → 分五步引导：iss → sub → kid → host → 私钥（可发「跳过」复用系统私钥）
/key           → 看当前用的是哪套
/key 默认      → 恢复系统默认
/key 校验      → 用当前 key 打一次实时天气
```

引导 5 分钟内有效，发「取消」中断。**私钥必须和该账号控制台里上传的公钥成对**，用别人的
iss/sub/kid 配自己的私钥只会得到 401。

## 指令

### /天气

```
/天气                查绑定城市的天气
/天气 杭州           临时查另一个城市
/天气 设置 杭州      绑定 / 更换城市
/天气 清除           解除绑定
```

第一次直接发 `/天气`，机器人会反问城市，90 秒内回一个城市名即可。

### /天气推送

```
/天气推送                                       列出所有规则
/天气推送 加 每天 07:30 内容=now,daily,sun       每天 7:30
/天气推送 加 每周 一,三,五 07:30 内容=daily,air  每周一三五
/天气推送 加 每月 1,15 09:00 内容=daily,indices  每月 1 号和 15 号
/天气推送 加 每小时 8-20 0,30 内容=now,air       8~20 点，每小时 00 分和 30 分
/天气推送 加 日出 -30 内容=now,daily,sun         日出前 30 分钟
/天气推送 加 日落 +15 内容=now                   日落后 15 分钟
/天气推送 改 1 时间=08:00 内容=now,daily,air     改第 1 条
/天气推送 改 1 标题=早报                         给规则起名，推送标题会用它
/天气推送 开 1　　关 1　　删 1
/天气推送 试 1                                   立即渲染一次给你看，不发到频道
```

内容项：

| key | 内容 | 额外调用 |
|---|---|---|
| `now` | 实况：温度/体感/天气/风/湿度/气压/能见度 | 1 |
| `daily` | 今天+未来 3 天 | 1 |
| `hourly` | 未来 12 小时 | 1 |
| `air` | AQI + 首要污染物 | 1 |
| `indices` | 运动/洗车/穿衣/紫外线 4 项 | 1 |
| `alert` | 当前生效预警（没有就不显示） | 1 |
| `sun` | 日出日落 | **0**（从 daily 里取） |
| `minutely` | 未来 2 小时分钟降水 | 1（仅中国） |

`每小时 8-20 0,30` 的意思是「8 点到 20 点之间，每小时的 00 分和 30 分」，一共 26 次/天。

### /雨雪提醒

```
/雨雪提醒                     查看配置
/雨雪提醒 开　　关
/雨雪提醒 加时段 08:00-12:00
/雨雪提醒 加时段 11:00-20:00   可加多个，命中任一时段就提醒
/雨雪提醒 列时段
/雨雪提醒 删时段 2
/雨雪提醒 间隔 10              轮询间隔（分钟，5-60）
/雨雪提醒 提前 60              提前多少分钟算「即将」
/雨雪提醒 开始 开　　结束 关    分别控制开始/结束提醒
```

时段支持跨零点写 `22:00-06:00`。不配时段等于全天可提醒。

### /预警推送

```
/预警推送               查看配置
/预警推送 开　　关
/预警推送 间隔 60       轮询间隔（分钟，5-360），默认 60
/预警推送 等级 橙       最低推送等级：蓝/黄/橙/红
/预警推送 升级 开       等级升高时是否再推一次
/预警推送 加时段 07:00-23:00
/预警推送 删时段 1
/预警推送 测试          手动查一次当前预警
```

### /额度

```
/额度      余额、本月应计、最近 24 小时请求量
```

**需要先在控制台开通权限**（默认关闭）：

1. 控制台 → 项目管理 → 点开凭据
2. 下滑到「控制台权限」
3. 勾选「允许访问财务汇总数据」和「允许访问请求量统计」
4. 保存

没开通时接口返回 `403 Security Restriction`，插件会直接提示你去做这一步。

另外：`/metrics/v1/stats` 只给最近 24 小时，**不是当月累计**。免费订阅的月度额度不在资源包
里，接口看不到剩余量——想看月度总量得自己在控制台看。

## 推送成本

| 模块 | 计算 | 次/月 |
|---|---|---|
| 灾害预警 | 1 次/小时，**一次调用覆盖全国所有地区** | 720 |
| 定时预报 | 10 条规则 × 2 次/天 | 600 |
| 雨雪提醒（1 城市，窗口 12h，10 分钟间隔） | 6/h × 12h × 30 | 2160 |
| 用户查询 | 500 次 × 4 | 2000 |

免费订阅 5 万次/月，余量充足。真正随规模增长的是雨雪提醒：**每多一个城市，月增约 2160 次**。

已做的成本控制：

- 预警用 `/v7/warning/list?range=cn` 全局列表，一次调用覆盖所有城市，只有城市真在列表里
  才去查详情。所以**预警成本与用户数无关**。
- 雨雪提醒先用逐小时预报的降水概率预筛，概率为 0 整轮跳过，不碰分钟降水接口；逐小时结果
  缓存 1 小时。
- 分钟降水只有中国区有数据，海外城市不要开雨雪提醒。

## 已知限制

- **分钟级降水只有中国**。海外城市雨雪提醒会一直查不到数据。
- **纯文本输出**，没有图文卡片。卡片要依赖容器里的 Typst/Playwright，渲染失败的代价是彻底
  收不到推送，先不做。
- **预警是轮询不是推送**。和风没有 webhook，任何声称"实时推送"的实现底层都是轮询。默认
  1 小时轮询，气象预警的提前量通常是 6-12 小时，够用。
- **预警列表是区县级**。市级 ID（如天津 `101030100`）不会出现在列表里，代码按 LocationID
  前 6 位（省市）前缀匹配，才能覆盖到下辖区县的预警。中国台湾省等地区的 ID 是 5 位字母数字，
  走精确匹配。
- 进程卡住超过一分钟会漏推该分钟的规则。30 秒 tick 下基本不会发生。

## 文件

| 文件 | 职责 |
|---|---|
| `main.py` | 插件类，只放 handler 与生命周期 |
| `qw/jwtlite.py` | Ed25519 签名 + JWT 签发（标准库） |
| `qw/client.py` | 和风接口封装、归一化、错误分类 |
| `qw/keys.py` | 默认 key + 会话 key + 分步引导状态机 |
| `qw/store.py` | 规则/配置/去重状态持久化 |
| `qw/schedule.py` | 规则引擎（纯函数，可单测） |
| `qw/render.py` | 纯文本渲染 |
| `qw/commands.py` | 指令执行（不依赖 AstrBot） |
| `qw/pushers.py` | 后台主循环与三个推送源 |

数据落在 `data/plugin_data/astrbot_plugin_qweather/`：`subs.json`（订阅与去重状态）、
`keys.json`（会话级 key）。**去重状态必须落盘**，否则重启会把当前所有预警重推一遍。

## 开发

```bash
# 离线单测（不需要 AstrBot，不需要网络）
python _smoke_qweather.py

# 真实接口验证（会消耗接口调用）
python _live_qweather.py
```

`main.py` 里的 `@filter.*` 必须留在 `main.py`——AstrBot 用 `handler_module_path` 精确匹配
handler 归属，写在其它模块会被静默丢弃。
